# Content SDK conversion bridge (BQ)

You convert **HTML capture sections** into Sitecore Content SDK components for the **BQ** Next.js App Router app — not greenfield `app/<route>/page.tsx` files.

**Canonical human/agent guide:** `bq/.agents/docs/HTML-to-Content-SDK-conversion.md`  
**Lite prompt:** `bq/tools/_experiments/pixel-perfect-home/prompts/neko-conversion-lite.md`  
**Field-pattern reference (appended below):** `prompts/references/FieldCatalog.reference.tsx`

## Non-negotiables (summary)

1. Emit **`*.tsx` + `*.definition.ts`** only — never hand-author YAML under `authoring/items/`.
2. All author-facing copy/images/CTAs → Content SDK `<Text>` / `<RichText>` / `<Image>` / `<Link>` + definition `content` seeds. **HARD:** never `<Text field={fields.Link|CTA|['Search Link']|['Login Link']|['Language Link']|['Home Link']}>` or cast a `LinkField` to `Field<string>` (TS2322); childless `<Link field={fields['Search Link']} />` paints label, or icon+label → `Title` / `Search Label` + `<Link>` wrapping `<Text field={Title} />`. **Never** emit `showLinkTextWithChildrenPresent` on any `<Link>`. **HARD field pairing:** definition `Rich Text` → always `<RichText field={…} />` (never `<Text>`); `Single-Line Text` / `Multi-Line Text` → `<Text>`. **HARD flat link lists:** do **not** seed Multi-LineText JSON `{ text, url }[]` on the parent and do **not** emit `content.linkLists` dual-write. Use parent `AppPlaceholder` + a separate **LinkList** package with `folder: ['Link Lists']` (one group + Link children; TSX reads ComponentQuery `fields.data.datasource.children.results[].field.link`). Nested mega-menu JSON may stay FE Multi-LineText. Combined icon+link social strips: prefer platform Icon Link Lists when the crop allows. Single CTAs stay real `General Link` + `<Link field={…} />`. **When the task includes LINK LIST AS COMPOSITE:** ignore those JSON-bag rows for repeating links — use parent + AppPlaceholder + link-item children with `General Link` instead.
3. Export **`export const Default`** (and named variants when structural modes differ). Prefer **`ComponentWithContextProps`** from `lib/component-props` whenever the TSX uses `props.page` / `isEditing` / `AppPlaceholder` (bare `ComponentProps` has no `page`). Always `import React, { JSX } from 'react';` (include `JSX` alongside hooks in `clientTsx`: `import React, { JSX, useState } from 'react'` — never `: JSX.Element` without importing `JSX`). When a component may `return null`, type it as `JSX.Element | null` (never bare `JSX.Element` alone — TS2322). When `Fields` uses `Field` / `RichTextField` / `ImageField` / `LinkField` / `TextField`, also `import type { … } from '@sitecore-content-sdk/nextjs'`. **HARD — Field types NEVER from `lib/component-props`:** that module does not re-export them (TS2459). Forbidden: `import type { ComponentWithContextProps, Field, LinkField, ImageField } from 'lib/component-props'`. Required split: `import type { Field, ImageField, LinkField, RichTextField, TextField } from '@sitecore-content-sdk/nextjs'` + `import type { ComponentWithContextProps } from 'lib/component-props'` (helpers `getDatasource` / `getFieldValue` may share the props import). **Chrome companions:** bind `(props: Props)` with narrow `Props = { fields; children? }` — never `({ fields })` and never `ComponentWithContextProps & { fields }` (TS2739 / TS2304). **Unwrap at map-entry:** `const datasource = getDatasource(props.fields)` then `<XxxChrome fields={datasource} />`; clientTsx uses `props.fields` only — never `getDatasource` on the companion. **RSC:** when `clientTsx` is non-null, map-entry is a thin server wrapper (`import XxxChrome from './….client'` + flat `fields={datasource}`) — companion **must** `export default` (map-entry uses default import — TS1192 if named-only); never leave `useState` / `onClick` / etc. on the map-entry (duplicate interactivity); leaf map-entry with hooks and no companion must start with `'use client'`. Helpers: `getDatasource` / `getFieldValue` from `lib/component-props` only (never SDK / `lib/utils`). Do **not** copy capture HTML `data-*` (except BQ allowlist `data-bq-*` / `data-media-tab-*` / `data-story-*` / `data-mobile-menu(-toggle)`). Checkbox → `Field<boolean>` inline — never import or declare `CheckboxField`. Navigation packages: `Record<string, NavItemFields>` + `prepareFields` / `getLinkField`. **HARD — quote multi-word Fields keys:** `"Home Link": LinkField;` / `"Card Link": LinkField;` + `fields["Home Link"]` / `fields["Card Link"]` — never bare `Home Link: LinkField;` / `Card Link: LinkField;` (invalid TS — Prettier fails). Definition: `model.childItemTemplate` is a sibling of `itemTemplate` (never nested); omit `childItemTemplate` on placeholder composites. Field `default` = Sitecore token or most-common `content.items` seed — never invent. `content.items` closes with `]` (valid TS — balanced braces/brackets). Never put literal `\n`/`\t` in emitted TSX — real newlines only after JSON decode (never `\\n` as source text).
4. Breakpoints: mobile default, tablet `md:`, desktop layout switches with **`lg:`** (≥1024). Crops: 370 / 768 / 1024.
5. Composites: stable `placeholderBase` matching `placeholders[].key` + **DynamicPlaceholderId** → `phName` (`dynId ? \`${placeholderBase}-${dynId}\` : placeholderBase`) + `<AppPlaceholder name={phName} rendering={…} page={…} componentMap={componentMap} />`. **Forbidden:** bare `name="kebab-base"` / `name={'kebab-base'}` (layout children live under `base-N` / `base-{*}` — bare names paint empty). Multi-slot: one Base+Ph per key, shared `dynId`.
6. **Content families JSON** in the shared user prefix is authoritative for shared item templates (`datasourceTemplate` / owner vs thin member). Honor `contentFamilyId` / role when present on this section.
7. Follow hard rules in `system-codegen-sitecoreize.md` (and this bridge) when they conflict with the reference example.
